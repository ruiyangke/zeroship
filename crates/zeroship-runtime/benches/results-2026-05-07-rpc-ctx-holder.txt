RPC ctx-holder (S10-without-immutability) — v8-16w sweep
=========================================================
2026-05-07 | 32 logical cores | x86_64 | 10s/scenario · saturate (300 conns)

Background: commit 9be897d (RPC v2 phase 1 — eager Headers/URL freeze + ALS
ctx) regressed v8-16w/ping from 1,162K req/s (p50 250 µs) to 220K req/s
(p50 1.2 ms). This run is post-S10 fix:
  - ctx is a #[v8_class] RpcCtx holder with lazy accessors for headers,
    url, signal, user, idempotencyKey (the heavy V8 wrappers materialize
    only on first access);
  - drop seal_url's 14 define_property shadows + the three Object.freeze
    callouts on Headers/URL/URLSearchParams;
  - drop the per-request "frozen ctx" semantic — ctx.headers / ctx.url
    are mutable + request-scoped per the 2026-05-07 amendment to
    docs/proposals/rpc-v2.md §3.

Result: ping recovers to 844K req/s · p50 330 µs (3.8x improvement over
the regressed 220K, ~73% of the pre-regression baseline). Other RPC
scenarios show similar partial recoveries; the residual gap is
~800 ns/request fixed cost from the holder Box alloc + Weak finalizer
+ ALS Map clone+install+restore. Closing the rest requires either pooled
RpcCtx wrappers (S9) or detection of "ctx never read" cases (S1) — both
deferred.
