=== Results after `__zsResponse` prototype-tag fix ===
Date: 2026-04-19 — after ee2fd5f + __zsResponse Response-shape fast-path
Setup: 16 workers on port 5101, 1 worker on port 5100, ZEROSHIP_DEV=1,
       nginx echo on 8888, 32-core NUMA split (servers node 0, client node 1).
Duration: 10s saturate · 300 conns · 16 client threads

Root cause summary:
  The "591k → 128k" regression in the original report compared two
  different workloads: the 591k figure was a benchmark run without
  ZEROSHIP_DEV=1, so every fetchExternal call returned a 500-fast via
  SSRF rejection (200 when wrapped in the old JSON-RPC envelope). The
  128k figure was a real fetch to in-NUMA nginx that actually crosses
  the event loop. Both pre- and post-ee2fd5f runtimes perform identically
  on both workloads (~128k real fetch, ~580k SSRF-reject). No real
  regression was introduced by ee2fd5f.

Fix (independent perf win regardless):
  - `Response.prototype.__zsResponse = 1` tag in fetch.js
  - `looks_like_response` now does ONE property read (tag inheritance)
    instead of TWO (`status` + `headers`) plus two V8 string interns
  - `classify_fulfilled` delegates to the same fast path
