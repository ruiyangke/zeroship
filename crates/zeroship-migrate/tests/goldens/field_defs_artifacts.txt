# The `schema.runtime.json` FieldDef corpus for step 4 consumer 3 of
# docs/proposals/single-fold-and-effects.md section G. Owned by
# crates/zeroship-migrate/tests/gen_types_field_defs_from_the_fold.rs.
#
# PROVENANCE, because a golden's worth is entirely its provenance.
#
# CAPTURED from the OLD path - `render_artifacts` driven by the retired `FieldDef`
# walker - by a separate, since-deleted binary, BEFORE the consumer was switched.
# Then 41 lines were REMOVED and 34 ADDED by hand. Every one of those 75 lines
# belongs to one of EIGHT carrier streams, and every one is a place where the
# deleted walker described a database the catalog does not have:
#
#   carrier:unique_constraint_dropped            `unique: true` outlived its dropped constraint
#   carrier:unique_constraint_kept               the same, with the un-dropped one as control
#   carrier:unique_column_facet_survives_a_drop  the same, with the COLUMN facet as control
#   carrier:check_bound_dropped                  `min`/`max` outlived their dropped CHECK
#   carrier:check_membership_dropped             `enum` outlived its dropped CHECK
#   carrier:check_column_dropped_and_readded     a re-added column inherited the bound
#   carrier:fk_column_dropped_and_readded        a re-added column inherited `onDelete`
#   carrier:attached_partition_dropped           a dropped partition stayed in the map
#
# NOT ONE line of the 27 RECORDED FIXTURES moved, and no other carrier moved. That is
# the behaviour-preservation result, and it is the reason the edits are auditable: the
# streams that changed are exactly the streams written to make the change visible.
#
# ---------------------------------------------------------------------------------
# SECOND EDIT, and the first that DOES move a recorded fixture. Six lines: the three
# `fluent_scalars|*|field|ledger|seq` rows gained `"precision":38,"scale":0`, and the
# three `runtime.json` shas moved with them.
#
# `ledger.seq` is `t.numeric({ precision: 38, scale: 0 })` - `ColType::Decimal` - and
# this golden had been recording it as a bare `{"type":"number"}`, indistinguishable
# from a `t.number()` float. That was not a golden defect; it was this corpus faithfully
# recording a lossy carrier. `col_type_to_token` spells `Decimal` and `Double` alike as
# `number`, so the SQLite emitter answered `REAL` for both and a 12-step rebuild
# re-declared the column REAL and copied its rows through a binary double.
# `tests/fold_live/sqlite_decimal_rebuild_live.rs` measures that against a real
# database: 12345678901234.5678 came back 12345678901234.6.
#
# So this edit is a DELIBERATE contract change, not a re-bless: the wire `FieldDef`
# gained two keys so the carrier can say "decimal", and these six lines are the whole
# blast radius across 27 fixtures, 23 carriers and 3 dialects. A reader auditing it
# should check exactly that - that `seq` is the only column that moved, and that it
# moved by gaining its authored precision rather than by changing its token.
#
# The 7-line net (-41 +34) is `attached_partition_dropped` alone: the relation `p1` is
# gone from the map, taking its two `field` rows on three dialects and its one
# `sqlite_create` row with it. Every other edit replaces a line with its successor.
#
# WHICH SIDE IS RIGHT is not decided by this file. For the first seven carriers it is
# decided by `fold_ops`, the structural catalog oracle the live PostgreSQL, SQLite and
# MySQL suites run against real servers, which has removed the constraint at the point
# the two answers differ. For the eighth it was decided by a live PostgreSQL in
# consumer 2's tests/env_db_ts_matches_the_server_pg.rs.
#
# THE SQLITE `sqlite_create` ROWS are the DDL leg: the `CREATE TABLE` the 12-step table
# rebuild renders from this map, through the same emitter and the same arguments
# render/declarative.rs passes. Exactly ONE of them moved, and
# tests/sqlite_rebuild_field_defs_live.rs measures - against a real SQLite database -
# that no stream carrying any of these five differences can be deployed there at all.
#
# THIRD EDIT. Removing dialectal fallbacks deliberately changes the two non-Postgres
# outcomes for the postgres-only `dialectal_ops` fixture. SQLite and MySQL now record
# one refusal apiece instead of artifacts for the prefix before the wrapper; an absent
# exact target leg is not permission to silently discard the operation.
#
# FOURTH EDIT, AND IT REVERSES THE THIRD. An `Op::Dialectal` whose `legs` map has no key
# for the render target now CONTRIBUTES NOTHING instead of refusing. `Expr::Dialectal`
# still refuses, and that asymmetry is deliberate. The two refusal lines the third edit
# installed are gone: -2 lines, +21, all on `fixture:dialectal_ops` under Sqlite and
# Mysql.
#
# The 20 `sha`/`field` rows are byte-identical to the Postgres rows above them with the
# dialect token swapped, `sha|runtime.json` INCLUDED (731b2f05… on all three dialects —
# the postgres-only leg declares an index, and no index reaches the `FieldDef` map). The
# `sha|env.db.ts` CONTROL is a5ce483e… on Sqlite and Mysql against 0e86a8cb… on
# Postgres, which is the absent `docs_embedding_hnsw_idx` in the OTHER artifact.
#
# THE 21ST ROW IS A REFUSAL THAT CHANGED ITS REASON RATHER THAN GOING AWAY, and it is
# the one line in this edit that a diff summary would mis-read as a no-op:
#
#   BEFORE  fixture:dialectal_ops|Sqlite|refused|gen-types: fold the declared ops into a
#           schema failed: fold: unsupported op: dialectal op has no leg for target
#           dialect
#   AFTER   fixture:dialectal_ops|Sqlite|sqlite_create_refused|docs|reserved system
#           field name: Field name 'id' is reserved by the active table-injection
#           policy. …
#
# The stream no longer stops at the fold, so it reaches the SQLite 12-step rebuild's
# `CREATE TABLE`, and the confined charter that owns the recorded fixtures injects `id`.
# That is not new behaviour: `ddl_create`, `fluent_scalars`, `p2a_facets` and
# `runtime_options` each already carry the identical `sqlite_create_refused` row for the
# identical reason, so `dialectal_ops` is the fifth confined fixture to record it and
# the first four are the control that says the reason is the charter, not the fold.
#
# FIFTH EDIT. `RuntimeSchemaDescriptorV1` became V2: every wire `FieldDef` gained the
# four read-surface flags `readable`/`filterable`/`sortable`/`projectable` and a
# `storage` block naming the physical column(s) the field occupies
# (crates/zeroship-migrate-core/src/render/gen_types.rs:320-360). The descriptor now
# CARRIES the second column's name instead of eight consumers deriving it with
# `format!("{col}_masked")`, so this is a contract change, not a re-bless.
#
# 407 of 582 rows rewritten; the row count did not move. The delta is fully classified:
#
#   90 of 90  `sha|runtime.json`   moved - every rendered stream embeds the new keys
#    0 of 90  `sha|env.db.ts`      moved - the CONTROL: V2 must not reach the authoring
#                                  artifact, and it did not
#  317 of 317 `field|` rows        moved
#    0        `refused|`, `sqlite_create|`, `sqlite_create_refused|` rows moved - the
#                                  DDL leg is untouched, which is the containment claim
#
# Every one of the 317 differs from its recorded twin by EXACTLY the five keys, appended
# in that order after the keys it already had, with no other byte changed and no row
# dropped or invented (0 dropped, 0 unmatched, 0 anomalies). 311 of the 317 `storage`
# blocks carry `valueColumn` alone; the other 6 also carry `auxiliary`, and they are the
# three vector columns (`dialectal_ops.docs.embedding`, `p2a_facets.posts.embedding`,
# `p2a_facets.posts.secondary_embedding`) on Sqlite and Mysql only - Postgres declares
# `Capability::NonBtreeIndexMethod` and indexes a vector in place, so it owns no shadow
# relation (gen_types.rs:255-282). NO row carries `rawColumn`: this corpus declares no
# masked or encrypted field, so the two-column arm is pinned by
# crates/zeroship-migrate-core/src/render/gen_types/physical_storage.rs, not here.
#
# There is deliberately NO re-bless environment variable, matching
# tests/op_fixture_goldens.rs and both predecessors.
