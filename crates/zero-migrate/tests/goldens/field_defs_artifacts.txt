# PROVENANCE, because a golden's worth is entirely its provenance.
#
# CAPTURED from the OLD path - `render_artifacts` driven by `fold_to_field_defs` - by a
# separate, since-deleted binary, BEFORE the consumer was switched. Then 41 lines were
# REMOVED and 34 ADDED by hand. Every one of those 75 lines belongs to one of EIGHT
# carrier streams, and every one is a place where the deleted walker described a
# database the catalog does not have:
#
#   carrier:unique_constraint_dropped            `unique: true` outlived its dropped constraint
#   carrier:unique_constraint_kept               the same, with the un-dropped one as control
#   carrier:unique_column_facet_survives_a_drop  the same, with the COLUMN facet as control
#   carrier:check_bound_dropped                  `min`/`max` outlived their dropped CHECK
#   carrier:check_membership_dropped             `enum` outlived its dropped CHECK
#   carrier:check_column_dropped_and_readded     a re-added column inherited the bound
#   carrier:fk_column_dropped_and_readded        a re-added column inherited `onDelete`
#   carrier:attached_partition_dropped           a dropped partition stayed in the map
#
# NOT ONE line of the 27 RECORDED FIXTURES moved, and no other carrier moved. That is
# the behaviour-preservation result, and it is the reason the edits are auditable: the
# streams that changed are exactly the streams written to make the change visible.
#
# The 7-line net (-41 +34) is `attached_partition_dropped` alone: the relation `p1` is
# gone from the map, taking its two `field` rows on three dialects and its one
# `sqlite_create` row with it. Every other edit replaces a line with its successor.
#
# WHICH SIDE IS RIGHT is not decided by this file. For the first seven carriers it is
# decided by `fold_ops`, the structural catalog oracle the live PostgreSQL, SQLite and
# MySQL suites run against real servers, which has removed the constraint at the point
# the two answers differ. For the eighth it was decided by a live PostgreSQL in
# consumer 2's tests/env_db_ts_matches_the_server_pg.rs.
#
# THE SQLITE `sqlite_create` ROWS are the DDL leg: the `CREATE TABLE` the 12-step table
# rebuild renders from this map, through the same emitter and the same arguments
# render/declarative.rs passes. Exactly ONE of them moved, and
# tests/sqlite_rebuild_field_defs_live.rs measures - against a real SQLite database -
# that no stream carrying any of these five differences can be deployed there at all.
#
