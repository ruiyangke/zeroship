# PROVENANCE, because a golden's worth is entirely its provenance.

# This file was CAPTURED from the OLD path - `render_artifacts` driven by
# `authoring_tables_from_ops` - before the consumer was switched, and then 81 lines
# were REMOVED and 72 ADDED by hand. Every one of those 153 lines belongs to one of
# eight carrier streams, and every one is a place where the deleted walker described a
# database the server does not have:
#
#   carrier:pk_replace_single           the key stayed on the replaced column
#   carrier:pk_replace_composite        the table-level clause never appeared
#   carrier:pk_drop                     `primaryKey: null` never appeared
#   carrier:pk_add                      `primaryKey: null` survived an installed key
#   carrier:pk_replace_drops_identity   `.autoIncrement()` outlived the dropped identity
#   carrier:pk_replace_then_renamed     both of the above, composed with a rename
#   carrier:pk_replace_then_drop        two alterPrimaryKey ops composed
#   carrier:attached_partition_dropped  a dropped partition stayed a table
#
# SIX of the eight are adjudicated directly by a live PostgreSQL in
# tests/env_db_ts_matches_the_server_pg.rs, which applies the migration for real, reads
# the answer out of pg_catalog, and asserts the artifact declares it. The two
# `_then_` streams are compositions of ops each of which IS adjudicated there.
#

# are byte-identical across the move. Every `sha|runtime.json` line was unchanged -
# `schema.runtime.json` is rendered from the `FieldDef` map and the runtime-metadata
# projection, neither of which CONSUMER 2 touches. No `constraint`, `index`,
# `partition_by`, `schema` or `options` line moved on any stream.
#

# `fold_to_field_defs` walker that produced the `FieldDef` map. They are
# `carrier:attached_partition_dropped` and `carrier:unique_constraint_lifecycle`, on

# dropped partition left in the map, and a dropped UNIQUE outliving its constraint). The
