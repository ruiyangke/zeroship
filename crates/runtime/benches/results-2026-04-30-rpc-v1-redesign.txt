=================================================================
  zeroship Runtime Benchmark — post RPC v1 redesign
  Comparison vs Apr 27 (pre-redesign baseline)
=================================================================

Setup (same for both runs):
  16 v8-server-compio workers
  300 saturate connections
  zerobench (open-loop, HDR-precise, mio/epoll)

Wire change:
  Apr 27   POST /_rpc/<method>     body = JSON array of positional args
                                   response = raw JSON value
                                   kernel fast path: dispatchRpc(method, body)
                                   bypasses Request construction
  Today    POST /_zs/v1/<id>       body = superjson { json: <input> } envelope
                                   response = { json: <result> } envelope
                                   kernel fast path: GONE — every request goes
                                   through default.fetch(request)
                                   adds: Request construction, URL parse,
                                   envelope unwrap (JSON.parse + .json extract),
                                   response envelope wrap (JSON.stringify({json}))
                                   per-procedure Zod input validation slot
                                   (no schemas declared in bench fixture, so
                                   the cost there is 0 — same as Apr 27)

Notes:
  - Ping-class (~zero handler work) loses 50% throughput. p99 went from
    ~600µs → ~4ms. The dispatch overhead is now a much larger fraction
    of per-request time when the handler is trivial.
  - Crypto procedures lose 36-38%. The amortization is better because
    the handler does real work (digest, sign, encrypt).
  - ECDSA P-256 keygen+sign improved 8%. Likely unrelated to dispatch —
    different optimization in v8 binding refactors over the cycle.
  - Across the board, p50 went up by ~150-250µs per request. That's
    roughly the cost of: Request construction + URL parse + body text
    read + JSON.parse + envelope unwrap + dispatch lookup + JSON.stringify
    + envelope wrap.

What real apps look like:
  At 400k req/s a single zeroship process can serve 400k QPS of trivial
  procedures. With Zod validation, DB calls, or any meaningful handler
  work, the dispatch tax disappears in the noise. The 2x regression
  matters for synthetic benchmarks; not for production.

Architecture trade taken:
  Drop the kernel fast path. Worth ~2x on hot dispatch but eliminates
  the parallel code path (dispatchRpc + invokeMethod + parseRpcArgs all
  gone), aligns with WinterCG's default.fetch model, and delegates ALL
  HTTP work to user.default.fetch (the synthetic entry handles routing).
