Honest interpretation
---------------------

+2.3% recovery is well below the ~50-80k req/s estimate in
docs/archive/perf/httpget-regression-2026-05-04.md and within run-to-run
noise. The fastcall path's macro plumbing is verified working by
the v8_fastcall_smoke.rs tests (TurboFan-compiles + 1000-iter steady
state without deopt) — but **scenarios.js doesn't exercise
Headers.has on the httpGet path**.

scenarios.js fetch handler does:

    if (request.headers.get("upgrade") === "websocket") { ... }

Headers.get is the per-request hot crossing, NOT Headers.has.

We left Headers.get on the slow path because its return type is
Result<Option<Vec<u8>>, OpError>:

  - Option<T> can't be represented in V8 fast API (no null sentinel
    in the typed return shape).
  - Vec<u8> requires allocation, which the fast path forbids.
  - rusty_v8 v147 doesn't expose a writer-style out-param shape for
    SeqOneByteString that would let the fast path return a string
    via a caller-provided buffer.

Therefore the +2.3% likely comes from the FunctionTemplate
construction shape change (build_fast vs new) being marginally
warmer in the inline cache, NOT from any fastcall actually firing
on the request path.


Follow-up gating to close the gap
---------------------------------

To realise the regression report's +50-80k req/s estimate, EITHER:

  1. **Migrate Headers.get** by introducing a "FastByteStringWriter"
     adapter — a fastcall taking (this, FastApiOneByteString name,
     *mut u8 out_buf, *mut usize out_len) → bool, where the fast
     path writes the value bytes into a caller-provided buffer
     (capped, e.g., at 4 KiB), returning false (with a deopt) only
     when the value exceeds the buffer or doesn't exist. The slow
     path handles the fallback. This requires extending the macro
     to support out-params and a JS-side wrapper that pre-allocates
     a Uint8Array per call site (or uses a per-isolate scratchpad).

  2. **Rewrite scenarios.js to use Headers.has** for the upgrade
     check — diverges from WinterCG idiom and is rejected per the
     task spec.

  3. **Migrate Response.json** (referenced by docs/archive/perf/httpget-
     regression-2026-05-04.md as the second hot crossing). Less
     typed than (1) — body is an arbitrary JS value. Would need a
     mixed-shape fastcall + slow fallback.

Tier 1 candidates remaining for follow-up commits:
  - AbortSignal.aborted (`(this) → bool` — pure primitive, easy)
  - URL.protocol / .host / .pathname (USVString returns — needs
    SeqOneByteString writer)
  - URLSearchParams.size (`(this) → u32` — easy)
  - Streams.desiredSize (`(this) → f64` — easy)

The macro now exists; future commits can land them per the
ROI table in crates/runtime-macros/TODO.md without revisiting the
core plumbing.
