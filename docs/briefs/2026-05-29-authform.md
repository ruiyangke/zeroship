## API
```ts
export type AuthFormMode = "signIn" | "signUp";
interface AuthFormValues { email: string; password: string; name?: string; }
interface AuthFormProps extends Omit<ComponentPropsWithoutRef<"form">, "onSubmit"> {
  mode?: AuthFormMode;                 // default "signIn"
  title?: ReactNode;                    // default per mode ("Sign in" / "Create account")
  description?: ReactNode;
  onSubmit?: (values: AuthFormValues, e: FormEvent) => void;  // consumer owns auth
  loading?: boolean;                    // submit Button busy + form disabled
  error?: ReactNode;                    // shown as a Banner intent=danger (live) above the fields
  showName?: boolean;                   // signUp: include a Name field (default true in signUp)
  submitLabel?: ReactNode;              // default per mode
  socialActions?: ReactNode;            // optional slot (provider buttons) + an "or" Separator
  secondaryAction?: ReactNode;          // e.g. a "Forgot password?" link (signIn)
  footer?: ReactNode;                   // default: the mode-switch prompt + link
  onModeSwitch?: (next: AuthFormMode) => void; // drives the default footer link
}
```
- Centered `Card` containing a `<form>` (compose the real `Form`): header
  (title heading + description), optional error `Banner` (intent="danger",
  `live`), the fields, the submit `Button` (full-width, `loading`), optional
  `secondaryAction`, optional `socialActions` (with a Separator labelled "or"),
  and a footer (mode-switch prompt + a `Button variant="plain"` that calls
  `onModeSwitch(other)`). Use `Center`/`Stack` for layout.
- **Fields per mode:** signIn = Email + Password (+ secondaryAction "Forgot
  password?"). signUp = (Name when showName) + Email + Password. Each is a real
  `Field`+`Input` with the correct `type` + **autocomplete**:
  email→`type="email" autocomplete="email"`; signIn password→
  `autocomplete="current-password"`; signUp password→`autocomplete="new-password"`;
  name→`autocomplete="name"`. All required.
- onSubmit: gather values from the form (uncontrolled inputs via FormData or
  controlled — keep simple: read from the native form on submit), call
  `onSubmit(values, e)`; `e.preventDefault()` is the consumer's call OR we
  preventDefault by default and pass values (document — default preventDefault so
  it doesn't navigate). loading → disable the fieldset + submit busy.
- `forwardRef`, data-slot vocabulary (auth-form / -header / -title / -error /
  -fields / -submit / -social / -footer), per-prop JSDoc.

## a11y
The `<form>` has an accessible name (aria-labelledby the title heading). Each
Field/Input is properly labelled with correct `type`+`autocomplete` (so password
managers work). The error Banner is a `live` region (role per Banner). Submit is
a real `type="submit"` Button; the mode-switch + secondary are real buttons/links
with clear text. Don't trap focus; tab order = fields → secondary → submit →
social → footer. forced-colors via composed components.

## Constraints
`--zs-*` only; no raw hex/px; logical properties; forced-colors + reduced-motion;
no "HIG"/"Apple"; pre-launch no-back-compat. NO real auth/network — presentational
(emits onSubmit). Social buttons are a consumer SLOT (don't bundle brand icons).
Export from `blocks/index.ts`; `@import` CSS into styles.css (Composed blocks);
story `layout: "fullscreen"`.
