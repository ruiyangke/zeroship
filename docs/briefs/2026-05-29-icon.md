# Slice brief: Icon primitive (Lucide)

Add governed icon support. An `Icon` primitive that wraps a **Lucide**
(`lucide-react`) icon component (or any SVG React component) with token-driven
sizing, `currentColor`, and a11y conventions. Lives in
`sdks/ui/src/components/Icon/` (a primitive → components/).

## Why `as`-based, not `name`-based
`<Icon as={Search}/>` (pass the Lucide icon component) is **tree-shakeable**
(only imported icons ship) and **type-safe**, vs a `name="search"` string map
that would bundle the whole set. Consumers (and the Builder agent, which
generates imports) do `import { Search } from "lucide-react"` and pass it.
Document a future `name`-based convenience as optional.

## Dependency
Add **`lucide-react`** (current stable, `^0.x` latest) as a runtime `dependency`
of `sdks/ui` (`pnpm add lucide-react --filter @zeroship/ui` or edit package.json
+ `pnpm install`). It's tree-shakeable and peer-deps React (already present).

## Foundation tokens (add to styles.css `:root`)
Icon sizes (rem, theme-invariant), aligned to the type/space scale:
```css
--zs-icon-sm: 1rem;     /* 16 */
--zs-icon-md: 1.25rem;  /* 20 */
--zs-icon-lg: 1.5rem;   /* 24 */
```

## API
```ts
import type { ComponentType, SVGProps } from "react";
export type IconSize = "sm" | "md" | "lg";
export interface IconProps extends Omit<ComponentPropsWithoutRef<"svg">, "ref"> {
  /** The icon component to render — a lucide-react icon (or any SVG component). */
  as: ComponentType<SVGProps<SVGSVGElement>>;
  /** Token size. Default "md". (Also accepts a CSS length via `style`.) */
  size?: IconSize;
  /**
   * Accessible name. When set, the icon is meaningful: role="img" +
   * aria-label. When omitted (default), the icon is decorative: aria-hidden.
   */
  label?: string;
}
```
- Render the `as` component with `className="zs-icon zs-icon--{size}"` (+ caller
  className), `data-slot="icon"`, `focusable="false"`. The SVG is sized via CSS
  (`inline-size`/`block-size` = the `--zs-icon-*` token) — DON'T pass a raw px
  `size` prop to Lucide; let CSS govern (token-pure). `stroke`/`color` inherit
  `currentColor` (Lucide's default) so the icon follows the surrounding text
  color — no color prop needed (consumers set color on the parent).
- a11y: `label` → `role="img"` + `aria-label={label}`; else `aria-hidden="true"`
  (decorative default — most catalog icons are decorative beside text).
- `forwardRef` to the svg; per-prop JSDoc.

## CSS (`Icon.css`)
```
.zs-icon { display:inline-block; flex:0 0 auto; vertical-align:middle; }
.zs-icon--sm { inline-size: var(--zs-icon-sm); block-size: var(--zs-icon-sm); }
.zs-icon--md { inline-size: var(--zs-icon-md); block-size: var(--zs-icon-md); }
.zs-icon--lg { inline-size: var(--zs-icon-lg); block-size: var(--zs-icon-lg); }
```
forced-colors: icons use `currentColor` so they map to system text color
automatically — add a `@media (forced-colors: active)` note only if needed.
No raw hex; the `1rem`/etc. live in the token block (rem, allowed).
