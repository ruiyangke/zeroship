# Slice brief: ListView block

A governed stacked list of item rows — leading (avatar/icon) · content
(title + description/meta) · trailing (actions/badge/chevron) — with dividers
and optional whole-row links. Generalizes the builder's row patterns
(LedgerRow-ish). Lives in `sdks/ui/src/blocks/ListView/`.

## API (dual surface)
```ts
interface ListViewItem {
  id: string;
  leading?: ReactNode;        // avatar/icon (decorative or labelled by content)
  title: ReactNode;
  description?: ReactNode;
  meta?: ReactNode;           // secondary trailing-aligned text (e.g. timestamp)
  trailing?: ReactNode;       // actions / badge / chevron
  href?: string;              // whole-row link (content area only — see a11y)
  onClick?: () => void;       // interactive row (alternative to href)
}
interface ListViewProps extends ComponentPropsWithoutRef<"ul"> {
  items?: ListViewItem[];
  divided?: boolean;          // hairline between rows (default true)
  density?: "comfortable" | "compact";  // default comfortable
  children?: ReactNode;       // compound parts (mutually exclusive with items)
}
// Compound: ListView.Item (li) + .Leading / .Content (.Title/.Description) / .Trailing
```
- Root `<ul data-slot="list-view">`; each item `<li data-slot="list-view-item">`
  laid out as a row: leading · content column (Stack: title + description) ·
  spacer/meta · trailing (Cluster). Use Stack/Cluster.
- **Interactive rows (a11y discipline, mirror Card):** when `href`, wrap ONLY
  the content (leading+title+description) in an `<a href>` (the whole "main" area
  clickable); the `trailing` (actions/menu/badge) stays OUTSIDE the `<a>` so we
  never nest interactives. When `onClick` (no href), same shape with a
  `<button>`-as-content OR a clickable wrapper — prefer `href`/`<a>`; for
  `onClick` keep the content in a `<button type="button">` and trailing outside.
  A non-interactive item is plain text. Document: don't put interactive trailing
  content inside an interactive row's main link.
- `divided` → `--zs-separator` hairline between `<li>`s (logical border).
  `density` changes row padding only.
- `items`/`children` mutually exclusive (dev-warn if both; items wins).
- `forwardRef`, per-prop JSDoc, data-slot vocabulary
  (list-view / -item / -leading / -content / -title / -description / -trailing).

## a11y
Semantic `<ul>`/`<li>` (list semantics). Interactive row = a real `<a>`/`<button>`
around the content only; trailing interactives are separate, focusable, outside
the row link. Leading icons decorative (`aria-hidden`) unless they carry meaning.
Keyboard: native. Focus-visible ring on the row link (`--zs-focus-ring-*`).

## Constraints
`--zs-*` only; no raw hex/px; logical properties; forced-colors + reduced-motion
(row hover); no "HIG"/"Apple"; pre-launch no-back-compat. Export from
`blocks/index.ts`; `@import` CSS into styles.css (Composed blocks); story
`layout: "fullscreen"`.
