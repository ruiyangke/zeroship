### [R13-T1] C-3 regression test does NOT reproduce the cluster panic — false-negative pin (CRITICAL, test-coverage-r13, NEW)

- **Files**: `crates/sandbox/src/snapshot_store_gcs.rs:1086-1145` (WT-only C-3 fix: replaces inline `compio::runtime::spawn_blocking` with named `std::thread::Builder::new()...spawn(...)`); `crates/sandbox/src/snapshot_store_gcs.rs:1391-1430` (WT-only test `c3_put_callable_from_non_compio_thread`); `crates/sandbox/src/snapshot_handler.rs:392-407` (the outer `compio::runtime::spawn_blocking` that ALREADY wraps the inner `store.put(...)` call — the cluster-context bug's setup); `crates/sandbox/src/snapshot_store_gcs.rs:1080-1119` at HEAD `42212c5c` (the panic-source still in place at HEAD, pre-fix).
- **Symptom**: the cluster-discovered C-3 panic (compio-runtime `Runtime::with_current` panic at `compio-runtime-0.11.0/src/runtime/mod.rs:119`: "not in a compio runtime") fires when `TieredSnapshotStore::put` is invoked from a `compio::runtime::spawn_blocking` worker thread — because that thread has NO compio runtime in TLS, and the inner `compio::runtime::spawn_blocking(...)` at `snapshot_store_gcs.rs:1096` tries to read from TLS. The WT test `c3_put_callable_from_non_compio_thread` invokes `Tiered::put` from a plain `std::thread::spawn` (lines 1410-1413 of the WT), which is meant to mirror the spawn_blocking worker context. **It does not.** I ran `cargo test c3_put_callable_from_non_compio_thread` against HEAD `42212c5c` (the C-3 code fix NOT applied, just the test alone) and it PASSED (`1 passed; 0 failed`). This means the panic the test claims to pin is not actually triggered by the test's setup. The test as written exercises the FIX-PATH (a `std::thread::spawn` invocation of `put` is what the fix enables) but does not exercise the BREAK-PATH (the pre-fix `compio::runtime::spawn_blocking` would have to panic for the regression to surface). The discriminator is that compio's TLS lookup in `Runtime::with_current` doesn't actually panic on plain `std::thread::spawn` workers in unit-test mode — likely because cargo's test harness keeps a fallback runtime alive, or because the `.detach()` path doesn't fully exercise the unwrap. Verified by running the test against HEAD `42212c5c` with the pre-fix `compio::runtime::spawn_blocking` body still in place: test passes.
- **Why it matters**: a regression test that doesn't reproduce the pre-fix failure mode provides no future-protection signal. If a future contributor (or a refactor) reintroduces `compio::runtime::spawn_blocking` inside a sync-trait `put` body, this test will pass green AND the cluster panic will return. The test's commit message will say "regression-pinned by `c3_put_callable_from_non_compio_thread`", which is misleading. The cluster-context test infrastructure to actually reproduce the failure would need to either (a) run the test under `#[compio::test]` and explicitly enter `compio::runtime::spawn_blocking` before calling `put` — this matches the cluster call site at `snapshot_handler.rs:397` — or (b) call `compio::runtime::Runtime::with_current` directly inside the test thread to assert the panic surface. The WT test does neither.
- **Action**: rewrite the test as `#[compio::test]`-async and have it invoke `Tiered::put` from inside a `compio::runtime::spawn_blocking(...)`-wrapped closure — mirroring the cluster call site at `snapshot_handler.rs:392-407`. Pre-fix this MUST panic the worker (assertable via `std::panic::catch_unwind` if compio's spawn_blocking surfaces the panic to the JoinHandle, otherwise via `tokio-style` `.unwrap_err()` on the await), and post-fix MUST return Ok. The current WT test is at best documentation; it does not detect a regression. Companion suggestion: add the same shape under `snapshot_handler::tests` driving `do_snapshot_inner` past the `spawn_blocking { store.put(...) }` hop, so the actual production call path is exercised, not just the trait-method-in-isolation. ~40 LOC for the rewrite; the existing WT test should be either deleted or renamed `c3_put_callable_from_plain_thread` so its contract isn't overstated.
