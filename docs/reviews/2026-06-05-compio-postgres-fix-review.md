# compio-postgres remediation re-review

**BOTTOM LINE.** The remediation is **sound to keep and push.** All 14 raw findings survived adversarial verification (14 confirmed, 0 refuted), and not one is a correctness, data-loss, or security defect in a reachable path. The pool, replication, and BINCOPY-1 fixes are correct and faithfully tested; the high-risk multiplex run-loop rewrite is cancel-safe, memory-safe, and preserves FIFO ordering / COPY-IN / NOTIFY / terminate semantics, verified by both code-tracing and live PG. The two genuine defects in the multiplex loop — a teardown resource leak (MUX-1) and a narrow large-bidirectional pipelining deadlock (MUX-DEADLOCK-1) — are both **medium**, both **conditional and unreachable by any current first-party caller**, and neither is a regression that should block the merge. There are **no must-fix (high/critical) issues.** Recommend pushing as-is and opening follow-up tickets for the two mediums plus the doc/test-depth nits.

## Recommendation

**Must-fix before push:** None. There are no high/critical findings; nothing is a reachable correctness, data-loss, or security defect. The remediation is sound to push as-is.

**Should-fix (open follow-up tickets, do not block the merge):**

1. **MUX-1** (medium) — retain the read task's `JoinHandle` and `cancel().await` it on every `run_multiplexed` exit (or `shutdown(SHUT_RD)` before returning) to close the teardown task/buffer/fd leak against half-open peers. Add the forced-write-error/hung-read regression test. This is the one true regression vs the serialized loop.
2. **MUX-DEADLOCK-1** (medium) — interleave the write flush with `read_rx` draining (or make the read channel unbounded) so concurrent large bidirectional traffic on one connection cannot wedge; soften the overstated "delivers concurrent read+write" doc claim.

**Nice-to-haves (low/info, batch into a docs/cleanup pass):**

- Fix the three `into_split` "dup's the fd" comments (**MUX-2**) — they are factually wrong and compound MUX-1's reasoning.
- Wire up `write_half.shutdown()` on the multiplexed terminate path or delete the dead `BufWriteHalf::shutdown` (**MUX-4 / MUX-NO-SHUTDOWN**).
- Delete the non-existent `write_buf` fallback-guard claim in `try_into_split` docs (**MUX-3**).
- Strengthen or re-scope the IO-3 pipelining test (**MUX-5 / IO3-TEST-WEAK**) and add the end-to-end LSN wire-path test (**REPL-N1**); both close test-depth gaps on otherwise-correct fixes.
- Make the POOL-1 cancellation test deterministic (**POOL-T24-FLAKY**) — fail-loud only, but worth de-flaking.

**Confidence in the highest-risk change (the run-loop multiplex):** Reasonably high that it is **correct and safe to ship**. The core cancel-safety design is verified sound both ways — the cancel-unsafe `read_backend` is confined to a detached task looped to completion, the main loop selects only over cancel-safe ops plus a fully-awaited flush, dropping a mid-flight read is memory-safe (deferred io_uring buffer reclaim, not UAF), and `detach()` provably does not cancel. FIFO ordering, COPY-IN (no desync; error batch held until trailing Sync), async NOTIFY/notice routing, and single-Terminate teardown were each verified by code-reasoning AND live Postgres 16. The two residual defects are both at the *edges* the design deliberately traded for (never-drop-an-in-flight-read costs cancelability → MUX-1; cap-1 channel + blocking flush → MUX-DEADLOCK-1), both medium, both unreachable by current callers. So: ship now, fix the two mediums next.

**Confidence in test faithfulness:** Good, with eyes open. The discriminating regression tests that matter most — POOL-1 RAII leak (`total_count()==1`), POOL-2 ordering + reclaim-on-drop, IO-2 idle-notify, COPY-1 deadlock (0.81s post-fix vs 15.2s pre-fix), and all REPL/BINCOPY unit tests — were traced against `git show main:` and run GREEN live against PG 16, and the COPY test specifically rejects a wedged/closed connection. The known soft spots are bounded and self-disclosed: IO-3 is non-discriminating (proven by a pre-fix-commit worktree run), and three guards (REPL-N1, REPL-N2) assert on extracted helpers rather than the public seams — all test-depth gaps on fixes that are independently verified correct, none masking a live defect.
