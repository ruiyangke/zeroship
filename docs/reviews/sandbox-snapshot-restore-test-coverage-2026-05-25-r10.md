### [R10-T3] R9-T7's `read_sandbox_id_from_sources` lacks the "env-empty falls through to file fallback?" cross-source test (IMPORTANT, test-coverage-r10)

- **Files**: `crates/sandbox-agent/src/handlers.rs:138-155` (`read_sandbox_id_from_sources` — branches: env-Ok-and-empty trips empty-id guard; env-Err goes to file); `crates/sandbox-agent/src/handlers.rs:2102-2204` (the 7 new R9-T7 tests).
- **Symptom**: the brief explicitly asked "is it tested across BOTH env-var-set + file-fallback in interleaved sequence (cross-source semantics)?". Reading the 7 tests: every test sets EITHER the env-var OR writes the file, never both. The semantic edge case "env var SET-but-EMPTY-string + file-PRESENT-with-valid-id" is **not** covered. Per line 139 (`if let Ok(v) = std::env::var(...) { v } else { ... read fallback }`), an empty env-var STRING (Ok("")) wins over the file fallback and then trips the empty-id guard — operators who deliberately unset by writing `SANDBOX_AGENT_SANDBOX_ID=` (vs `unset SANDBOX_AGENT_SANDBOX_ID`) would see the agent fail boot even though `/run/keys/sandbox-id` is valid. This semantic is load-bearing (production wrappers vary on which they do) but uncovered.
- **Why it matters**: the cluster's wrapper currently passes the id via env-var (B24 fix `a4c481e1`), but a future migration to file-only (e.g., per the systemd LoadCredential pattern) might leave the env-var set to an empty string from an old unit override. With no test pinning "env=empty + file=valid → error not fallback", a contributor fixing this surprise as a feature (envOk("") falls through to file) lands green and breaks the existing pin in `r9t7_read_env_var_empty_string_rejected` only by name — the new behaviour would silently differ from documented contract. Pin both directions.
- **Action**: two cross-source tests:
  1. `r10_t3_env_empty_does_not_fall_through_to_file_fallback` — set env to `""`, write valid id to fallback file, assert `Err("sandbox_id is empty")` (pins current "Ok(\"\") trumps file" semantics).
  2. `r10_t3_env_present_wins_over_file_when_both_valid` — set env to id_a, write id_b to fallback file, assert returned id == id_a (pins env-precedence). The brief's "interleaved sequence" wording suggests this second test specifically.
  Each ~10 LOC under the existing `SANDBOX_ID_ENV_LOCK` serialization.
