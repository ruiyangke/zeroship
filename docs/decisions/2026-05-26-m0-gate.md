# 2026-05-26 M0 Exit Gate Harness

## Decision

The M0 gate is a faithful real-path e2e harness, not a mocked agent test. `tests/m0_gate.sh` brings up Postgres, the Docker sandbox controller, the real control plane, one worker, the gateway, and one Builder Vite dev server on `:3001`. The Playwright project in `apps/zeroship-builder/playwright.m0.config.ts` runs the B3 deploy-tool and live-preview proxy specs, then `e2e/m0-gate.spec.ts`.

Each M0 prompt creates a real control-plane app, sends a realistic creator request to `apps/zeroship-builder/src/server/chat.ts` via `POST /_zs/v1/chat`, waits for the real `createDeepAgent`/`ChatOpenAI` turn to write files in the Docker sandbox, requires the real `deploy` tool to return a deploy hash, and fetches the deployed app back through the gateway.

## Prompt Set

The fixed set lives in `apps/zeroship-builder/e2e/m0-prompts.json`:

1. `todo-board` - task CRUD, done filter, remaining summary.
2. `markdown-notes` - note editor, markdown preview, search.
3. `url-shortener` - local short-code manager and demo click counts.
4. `poll-voting` - question/options, votes, totals, reset.
5. `guestbook` - validated name/message form and recent messages.
6. `expense-tracker` - amount/category/note entries and totals.
7. `link-in-bio` - public profile, featured links, signup, local editor.
8. `habit-tracker` - seven-day habit grid and streaks.
9. `countdown-timer` - configurable event countdown and finished state.
10. `contact-form` - validated lead form, success receipt, local lead list.

Per-prompt pass criterion: the app compiles in the sandbox, the real deploy tool approves and uploads `dist/app.zship` to `/api/apps/{id}/deploy`, the control plane records a deploy hash, and the live gateway URL returns a non-empty rendered page that is not the starter app.

## Bring-Up

`tests/m0_gate.sh` prints and executes the bring-up commands. Defaults:

- Postgres: `docker compose up -d postgres`, `:5440`.
- Sandbox: `./tests/sandbox_up.sh`, `:9091`, token `zeroship-sandbox-local-harness-token-2026-05-26`.
- Control: `target/release/zeroship-control --port 9090 --db postgres://postgres:zeroship@127.0.0.1:5440/zeroship --bundles .zeroship/m0-gate/bundles --control-key dev-master-key --master-key dev-master-key`.
- Worker: `target/release/zeroship-worker --port 8080 --workers 2 --control http://localhost:9090 --control-key dev-master-key --poll-interval 2`.
- Gateway: `target/release/zeroship-gate --port 8000 --control http://localhost:9090 --control-key dev-master-key --workers http://localhost:8080 --poll-interval 2`.
- Builder: `npm run dev -- --host 127.0.0.1 --port 3001 --strictPort` in `apps/zeroship-builder`.

The script kills only numeric PIDs found on those ports or PIDs it started. It does not use `pkill -f`.

## Time Bounds And Resumability

Every prompt is wrapped in `M0_PROMPT_TIMEOUT_MS` (default `330000`, 5.5 minutes). Timeout means that prompt fails and the spec continues. Results are written after every prompt to `.zeroship/m0-gate/results.json`; `M0_RESUME=1` skips prompts already recorded as passed. `M0_LIMIT` or `M0_ONLY` can run a partial proof without changing the default full 10-prompt gate. The full run asserts `>=7/10`; partial runs default to reporting the real tally without asserting the 7-prompt threshold.

## Sandbox Template

The Docker sandbox base image now includes Node/npm, git, tar, zstd, and the signed sandbox agent. It seeds an empty workspace with the default React/Vite app and a build script that emits `dist/app.zship`. This is platform scaffolding for the real path: the deploy tool still runs Reviewer, `npm run build`, artifact download, and the real control-plane deploy endpoint.

## Flakiness Notes

Record observed per-prompt failures and timeouts here when the gate is run. The initial harness implementation leaves failed app records in the dev database with unique `m0-*` names so their control-plane state can be inspected after a run.
