# AI Builder Feature Landscape — April 2026

> Written as competitive intelligence for zeroship. Covers what competing AI
> app builders actually *do* when a creator prompts them — product/UX/technical
> capabilities, not funding or pricing (those are in the prior research note).
>
> Where a feature is uncertain or marketing-only, I've flagged it explicitly.
> Anything marked **(verify)** should be double-checked before making a
> strategic call on it.

## How to read this

Each Tier-1 profile applies a consistent template:

- **Input**: what modalities the tool accepts as creator input
- **Scope**: frontend-only / full-stack / backend-only / mobile
- **Stack**: the tech stack actually produced
- **Edit model**: regenerate vs surgical-edit granularity
- **Iteration UX**: how the creator refines after the first generation
- **Preview**: where/how the working app is rendered during iteration
- **Deploy**: deployment target and one-click-ness
- **Data/DB**: backend provisioning and schema management
- **Auth / Payments / Storage / Real-time**: whether built-in or DIY
- **Integrations**: connector catalog, MCP, npm
- **Version control**: git / snapshots / undo
- **Mobile**: web-only, PWA, RN, native
- **Error recovery**: does the AI self-debug
- **Agent architecture**: single-shot, planner+worker, multi-agent
- **Models**: which LLMs power it
- **Sandbox**: where the iterating app actually runs
- **Observability**: what the creator sees at runtime
- **Pain points**: what users complain about in their AI features
- **Recent updates**: what shipped late 2025 / Q1 2026

## Tier 1: Full Profiles

### Lovable (lovable.dev)

**Input.** Text prompt + image upload + **Figma import** (Feb 2025). URL import
(paste any URL → clone the layout) added mid-2025. Screenshot-to-UI is solid.

**Scope.** Full-stack when Lovable Cloud is enabled: React frontend + Supabase
backend (Postgres, auth, storage, edge functions) auto-provisioned per project.
Without Cloud, frontend-first with handoff-to-Supabase guidance.

**Stack.** Fixed: **Vite + React + TypeScript + Tailwind + shadcn/ui**, plus
react-router or Next-compatible routing. Deviating from this stack is awkward
— the prompting assumes it. Supabase on the backend. No Vue/Svelte/Astro
support (vs Bolt).

**Edit model.** Two modes: **Chat mode** (surgical — "change this button's
color") and **Default mode** (regenerate — broader rewrites). Click any element
in the preview → Lovable highlights it in the file tree and biases the next
prompt toward that file. "Chat Only" mode (no edits, just Q&A) added late 2025.

**Iteration UX.** Chat + live preview right panel. File tree + code editor
accessible via "Dev Mode". Undo per-message. "Revert" snapshots, you can
rewind to any earlier state of the project.

**Preview.** Inline iframe, hot-reloads on every AI edit. Mobile preview toggle.
Preview deploys to an autogenerated subdomain (`<slug>.lovable.app`) so you can
share a link.

**Deploy.** One-click publish to `.lovable.app` with Cloud. Custom domain on
paid tiers. GitHub sync (two-way) — user can push to their own GitHub and
deploy elsewhere (Vercel, Netlify).

**Data/DB.** **Lovable Cloud** (launched Nov 2025) auto-provisions a Supabase
project per workspace. The AI generates schemas, RLS policies, and queries via
Supabase client SDK. Schema migrations are **additive only in practice** —
changing column types still requires manual SQL. **Row-level security
incidents**: widely publicized report that 170 of 1,645 Lovable apps had
critical RLS holes exposing auth'd user data — Lovable pushed an RLS hardening
update Q4 2025 in response.

**Auth.** Supabase Auth wired by default — email/password, magic link, Google,
GitHub OAuth. Sessions managed client-side.

**Payments.** **Stripe native integration** via Stripe Billing (Lovable is a
Stripe Billing case study). Creator connects their Stripe account; Lovable
generates checkout pages, customer portals, webhook handlers. This is creator-
facing billing (your users pay YOU via your Stripe). No marketplace cut.

**Storage.** Supabase Storage — S3-compatible buckets, CDN, image transforms.
Upload UI components generated automatically.

**Real-time.** Supabase Realtime: Postgres changefeeds over WebSocket.
AI generates subscriptions for collaborative/live features.

**Env / secrets.** Managed per-project secrets vault. Creator pastes API keys;
they're injected into the runtime env, not visible to end users.

**Integrations.** Supabase-native (row-level integrations only). MCP support
**(verify — may have shipped Q1 2026)**. Can `npm install` arbitrary packages.
OpenAI/Anthropic/ElevenLabs prefabs in prompt library.

**Collaboration.** Team workspaces (Teams plan). Multi-player editing
**(verify — announced but UX rough per user reports)**.

**Version control.** GitHub sync (two-way). Per-message snapshots; "Remix" to
fork any project. No git branches visible in UI.

**Mobile.** Web / PWA only. No React Native, no App Store path.

**Error recovery.** AI self-debugs on runtime errors it can observe (compile
errors, server 500s visible to the preview). This consumes credits; **top user
complaint**: "AI bills me to fix what the AI broke."

**Agent architecture.** Single chat agent with tool use. Reads/writes files via
tools; re-runs build on every edit. No explicit planner/worker split visible
to the user.

**Models.** Primary: **Claude Sonnet 4.5/4.6** for codegen. Also routes to
GPT-4o for certain non-code tasks. Users can't pick the model.

**Sandbox.** Each project runs in a server-side sandbox (WebContainer-like but
remote). Preview iframe points at the sandbox URL.

**Observability.** Supabase logs + function logs visible in Cloud dashboard.
No APM-style view; creator sees errors but not structured traces.

**Pain points**:
- Credit consumption for AI self-fix loops is the #1 complaint (Reddit,
  Twitter, Hacker News). Users report ~30-50% of credits go to fixing the AI's
  own mistakes.
- RLS misconfigurations (now remediated, but reputational damage remains)
- "Getting stuck on a bug" — AI regenerates the same broken pattern 3-5 times
- Fine-grained CSS edits regenerate too much of the component
- Mobile preview shows layout OK but generated code isn't truly responsive

**Recent updates (6 months)**:
- **Lovable Cloud** (Nov 2025): auto-Supabase provisioning
- **Visual Edit Mode** improvements (click-to-edit, inline styling)
- **Agent 3** (Dec 2025): better multi-file refactors, RLS-aware generation
- Figma → Lovable refinement
- Stripe Billing deeper integration (Feb 2026)
- $330M Series B at $6.6B (Dec 2025) — signals aggressive feature push

### Bolt.new (StackBlitz)

**Input.** Text prompt. Image upload for UI reference. No Figma import (as of
Q1 2026 — **verify**). `git clone <url>` in the terminal works because it's a
real Node environment.

**Scope.** Full-stack web. Can scaffold frontend-only or full-stack-with-API.
Mobile added via Expo templates (Oct 2025).

**Stack.** **Flexible** — this is Bolt's biggest technical differentiator.
Supports React, Vue, Svelte, Astro, Next.js, Nuxt, Remix, SolidJS, etc. The
AI picks or follows the creator's prompt. Backend: any Node framework
(Express, Hono, Fastify). Bolt.new is essentially a generalized Node.js
sandbox with an AI agent attached.

**Edit model.** Surgical. Bolt's `<boltArtifact>` / `<boltAction>` XML
convention in prompts lets the model describe precise file edits (create,
modify, shell command). This is leaked/documented in their system prompt.
Users report edits are more targeted than Lovable's but less visual.

**Iteration UX.** Chat + full file tree + code editor + terminal, all in a
three-pane layout. The terminal is real — you can `npm install`, `curl`, run
scripts. Preview in iframe.

**Preview.** **WebContainer-based** — the app runs *in the creator's own
browser*, not on Bolt's servers. This is Bolt's signature: StackBlitz built
WebContainers, a WASM-compiled Node.js runtime. Zero server-side compute cost
for iteration = why Bolt can afford generous free tiers. Preview is genuinely
instant (ms-level reloads).

**Deploy.** **Netlify partnership**: one-click deploy, ~1M+ sites deployed
this way (per Netlify data). **Bolt Cloud** (own hosting, launched 2025) is
rolling out for apps that need server-side compute (WebContainer can't persist
state beyond the browser session). Supabase integration for DB.

**Data/DB.** Supabase (most common), or any `npm install`-able DB client
(Prisma + any DB). No auto-provisioning — creator wires it up (the AI does
this for you but the actual Supabase project is creator-owned).

**Auth.** DIY via Supabase Auth, Auth.js, Clerk, etc. — generated on demand.
No proprietary auth.

**Payments.** Stripe via `npm install stripe`. Expo templates include Stripe
Mobile SDK.

**Storage.** Whatever the chosen stack supports (Supabase Storage, S3 via
SDK).

**Real-time.** WebSockets via ws / Socket.io / Supabase Realtime. Generated
on demand.

**Env / secrets.** `.env` files in the WebContainer. Secrets flow to Netlify
env on deploy. Creator manages them directly.

**Integrations.** Full npm ecosystem (with WebContainer limitations — some
native-addon packages don't work). Figma is missing. Supabase + Netlify
partnerships are the productized ones.

**Collaboration.** Single-user per session. No multiplayer editing.

**Version control.** Git in the WebContainer works. "Fork" snapshots.
GitHub repo integration added 2025.

**Mobile.** **Expo / React Native** templates (Oct 2025). Swift native —
**no** (that's Rork's territory).

**Error recovery.** AI sees terminal output + browser console. Loops to fix
compile errors / runtime errors automatically. Token-based pricing means
each fix attempt eats tokens → same credit-burn complaint as Lovable.

**Agent architecture.** Single-agent with tool use via the XML
`boltArtifact/boltAction` protocol. The agent can propose a plan or dive
straight into file edits depending on prompt.

**Models.** Claude Sonnet 3.7 → 4.x (verify — they moved to 4.x Q4 2025).
Users on higher tiers can select Claude or GPT. "Bolt V2" (Oct 2025) claims
98% reduction in error loops vs V1.

**Sandbox.** WebContainer in the browser — this is the architectural moat.
No server iteration cost = Bolt can serve many free users cheaply.

**Observability.** Browser devtools + terminal output. For deployed Bolt
Cloud apps: basic logs (verify).

**Pain points**:
- **WebContainer limitations**: some npm packages with native binaries fail;
  Prisma, Playwright, Puppeteer all have caveats
- Large apps slow down the browser (all state is client-side)
- No way to share the iterating app — the running preview is local to the
  creator's browser
- Deploy to production still requires server hosting (Netlify/Bolt Cloud)
- Credit burn on self-fix loops (same as Lovable)

**Recent updates**:
- **Bolt V2** (Oct 2025): enterprise-grade, 98% error-loop reduction
- **Mobile templates** via Expo (Oct 2025)
- **Bolt Cloud** rollout (2025 — own hosting beyond WebContainer)
- Stack expansion (added Astro, Solid, etc.)

### v0 (Vercel)

**Input.** Text prompt. **Image-to-UI** (upload a mockup or screenshot —
shadcn-quality React output). Figma import **(verify — announced mid-2025)**.
GitHub repo import (Feb 2026).

**Scope.** Originally **frontend-only** (React components, pages). Since
**v0 Sandbox** (Feb 2026): can execute server code → full-stack via Next.js.
Still UI-first; backend is less mature than Lovable.

**Stack.** **Next.js App Router + React + Tailwind + shadcn/ui** — very
opinionated. Vercel's own stack. Can target Remix/Vite but not idiomatic.

**Edit model.** Both: generative streaming (regenerates chunks of UI as you
watch) and surgical "change just this" via selection. Version history per
generation — you can rewind, branch, or cherry-pick pieces across versions.

**Iteration UX.** Chat + streaming generative preview. The preview literally
streams the JSX as the model emits it. Inline element selection → "change
this" is smooth. Branching is first-class (new generation forks, easy to
compare).

**Preview.** Inline streaming iframe. Fast — Vercel's infrastructure is
behind it. Mobile/tablet preview.

**Deploy.** **Native Vercel deploy** — literally one click. Full Vercel
feature set: SSL, CDN, serverless functions, image optimization, analytics,
edge config. Tightest runtime integration of any AI builder.

**Data/DB.** **Vercel Postgres** (Neon-backed), **Vercel KV** (Upstash
Redis), **Vercel Blob** (S3-backed). AI generates connection code against
Vercel's SDKs. Schema migrations: weak — Drizzle is the conventional path
but the AI doesn't reliably handle migrations.

**Auth.** Auth.js / NextAuth patterns generated. No proprietary auth.

**Payments.** Stripe via generated code. Vercel has no marketplace cut.

**Storage.** Vercel Blob (S3-compatible) — upload components generated
against it.

**Real-time.** Server-sent events (Vercel supports streaming responses
natively). WebSockets via edge functions (limited — 30s timeout).

**Env / secrets.** Vercel env vars — multi-environment (dev/preview/prod).
Strong.

**Integrations.** Strong with Vercel ecosystem (Postgres/KV/Blob/Sentry/
PostHog). npm any package. MCP **(verify — Vercel added MCP support late
2025)**.

**Collaboration.** Team workspaces via Vercel Teams.

**Version control.** Every generation is versioned and diffable.
GitHub integration on deploy. Not a real git workflow in v0 itself.

**Mobile.** PWA. No React Native, no native.

**Error recovery.** AI sees generation errors; can iterate. No equivalent
of Lovable/Bolt's "watch it self-fix a runtime bug" loop publicly shown.

**Agent architecture.** Uses Vercel's internal v0 model (fine-tuned
GPT-4 variant — verify exact lineage) + tool use for Sandbox execution.

**Models.** **v0 model** (proprietary, fine-tuned). Was based on GPT-4;
now likely blends Claude/GPT under the hood (verify).

**Sandbox.** v0 Sandbox (Feb 2026) — ephemeral Node.js runtime in Vercel's
infra. Can execute server code for testing. For preview of pure UI, renders
directly in-browser.

**Observability.** Vercel Analytics, logs, Speed Insights — all standard
Vercel stack once deployed.

**Pain points**:
- Strongest for **UI generation**, weakest for **backend logic** — users
  note v0 produces great components but underwhelming database code
- Very tied to Next.js; if you don't want Next, v0 fights you
- Less "full app" than Lovable — more "fancy component/page builder"
- Credit/token pricing (switched Feb 2026)

**Recent updates**:
- **v0 Sandbox** (Feb 2026): server-side execution, full-stack apps
- **GitHub repo import** (Feb 2026)
- **Token-based pricing** (Feb 2026, replacing credits)
- Deeper Vercel SDK integration throughout

### Replit (Agent + Agent 3)

**Input.** Text prompt. Image upload. URL clone. Voice (mobile app). Multi-
file uploads accepted as context.

**Scope.** Full-stack, any language. Replit is a general cloud IDE with an
agent overlaid on top — the broadest scope of any competitor.

**Stack.** **Any** — Python, Node, Go, Rust, Ruby, Java, even C++. Popular
templates: Next.js, FastAPI + React, Flask, Django, Express. No strong
stack opinion; the agent picks based on prompt.

**Edit model.** Mix. Agent 3 (Oct 2025) handles multi-step multi-file tasks
— can run for **hours** on complex refactors. Direct code editing always
available in the IDE. "Assistant" chat is conversational; "Agent" is
autonomous.

**Iteration UX.** Full IDE (VS Code-like) + agent chat + preview pane.
More developer-oriented than Lovable's chat-first UX. Terminal, debugger,
multi-file find-and-replace all present.

**Preview.** Web-based preview via Replit's proxy. Mobile preview. For
native apps: emulator.

**Deploy.** **Replit Deployments** — autoscale (serverless containers),
reserved VM, scheduled jobs, static. Always-on mode for real apps. Custom
domains. Deeply integrated with their runtime.

**Data/DB.** **Replit Database** (KV built-in), **Postgres** (hosted),
Supabase integration. Agent 3 generates schemas + migrations.

**Auth.** **Replit Auth** (OIDC) — add a one-line config, Replit handles
OAuth with Google/GitHub/etc. Solid.

**Payments.** Stripe via generated code. No marketplace cut from Replit.

**Storage.** Replit Object Storage (S3-compatible). Generated upload UI.

**Real-time.** WebSockets natively supported. AI generates Socket.io or
raw ws.

**Env / secrets.** Secrets UI in IDE. Injected as env vars.

**Integrations.** GitHub import/export, Supabase, Stripe, OpenAI, all via
npm/pip. MCP (**verify**). **Connectors catalog** (Oct 2025).

**Collaboration.** **Multiplayer editing** (Google Docs-style, years ahead
of everyone). Teams plans. Comments on code.

**Version control.** Git natively. Checkpoints per agent run.

**Mobile.** **Replit Mobile** iOS/Android (Feb 2025) — code on phone.
**Mobile Apps** (Replit's app-targeting feature): build React Native apps,
submit to App Store from the Replit IDE. Closest thing to Rork in integrated
workflows.

**Error recovery.** Agent 3 is specifically designed for long self-debug
loops. Can run tests, read failures, iterate autonomously for hours.
Strongest self-debug loop of any competitor per public benchmarks (**verify**).

**Agent architecture.** Agent 3: multi-step planner + worker + verifier.
"Vibe coding in the background" — can queue tasks and leave.

**Models.** Claude Sonnet 4.x + GPT mix. User can select in some modes.
Rumored Agent 4 in development.

**Sandbox.** Replit's own Linux container infrastructure. Every project is
a real VM/container.

**Observability.** Runtime logs, metrics, deployment analytics — full.

**Pain points**:
- **"Context rot"** in long agent sessions — agent loses track of earlier
  decisions (well-documented user complaint)
- Agent sometimes rewrites files that were working fine
- Dev environment feels developer-centric; non-coders get lost in the IDE
- Expensive at scale ($20 → $100+/mo for real usage)

**Recent updates**:
- **Agent 3** (Oct 2025): multi-hour autonomous coding, 10× context
- **Replit Mobile** and **Mobile Apps** (Feb 2025)
- **Bounties deprecated** (2026) — retreated from marketplace
- Deeper Claude 4 integration

### Firebase Studio (Google)

**Input.** Text prompt, URL clone, screenshot. Gemini multimodal so it
accepts image context naturally.

**Scope.** Full-stack, with heavy Firebase bias.

**Stack.** **Wide language support**: Go, Java, .NET, Python, Android,
Flutter, React, Angular, Vue, iOS. Unusually broad. Default web template:
Next.js + Firebase.

**Edit model.** Both agent-driven and manual. Code OSS (VS Code) IDE
underneath. Gemini inline completions + chat agent.

**Iteration UX.** Cloud-based VS Code + Gemini agent + preview. 3 free
workspaces; 10 for Google Developer Program members; 30 for Premium. Per-
workspace state.

**Preview.** Integrated preview via Firebase Hosting Emulator + cloud
preview URLs.

**Deploy.** **Firebase App Hosting**, **Cloud Run**, **Firebase Hosting
(static)**. Deep Google Cloud integration throughout.

**Data/DB.** **Firestore** (default), Cloud SQL, BigQuery, Realtime
Database. Schema-less by default (Firestore = document DB, not SQL).

**Auth.** **Firebase Authentication** — social providers, magic link,
SMS, enterprise SSO. Battle-tested at Google scale.

**Payments.** Stripe via Firebase extension. Google Pay. No Firebase cut.

**Storage.** **Firebase Cloud Storage** (GCS-backed).

**Real-time.** **Firestore real-time** (native subscriptions, best-in-class).

**Env / secrets.** Google Secret Manager integration.

**Integrations.** Firebase Extensions catalog (~50 first-party),
Google Cloud services, plus npm/pip/etc.

**Collaboration.** Workspace sharing. Multi-user IDE (verify multiplayer).

**Version control.** Git in the IDE. GitHub/GitLab integrations.

**Mobile.** **Native** — Android Studio integration, **iOS via Flutter** or
Xcode Cloud. Best native mobile story among hosted builders.

**Error recovery.** Gemini agent iterates on errors it sees in the preview.

**Agent architecture.** "App Prototyping Agent" → "Full-stack vibe coding"
(rebranded March 2026). Planner + executor. Uses Gemini tool use.

**Models.** **Gemini 2.5 Pro / Flash / Code** — user can't pick non-Google.
**Note: overlapping product with Google AI Studio's Build mode**, which also
lets Gemini generate + deploy apps. Two-team internal competition.

**Sandbox.** Google Cloud workspaces (managed VMs).

**Observability.** Firebase dashboards, Cloud Logging, Cloud Monitoring —
enterprise-grade.

**Pain points**:
- **Tightly coupled to Firebase** — you can leave but losing the primitives
  hurts
- **Non-relational DB** default (Firestore) — AI sometimes generates awkward
  denormalized schemas when the app would be better with SQL
- Less polished chat UX than Lovable; more IDE-feel
- Google strategic uncertainty (see AI Studio duplication)

**Recent updates**:
- **Rebrand** to Firebase Studio (April 2025)
- **Full-stack vibe coding** (March 2026)
- **Gemini 2.5** integration
- **AI Logic** (previously Vertex AI in Firebase) for easier model access

## Tier 2: Focused Profiles

### Claude Artifacts + leaked full-stack builder (Anthropic)

**Artifacts (public)**: generated code/apps run in a sandboxed iframe in the
Claude chat. June 2025 upgrade added **full app creation with embedded AI**
(apps can call `window.claude.complete` for LLM calls). Persistent storage
for Pro/Max/Team/Enterprise users (files, sqlite-like). 500M+ artifacts
created. React primarily; Svelte, plain HTML supported.

**Leaked full-stack builder (Dec 2025 screenshots)**: Live previews,
integrated DB, auth primitives, one-click deploy inside Claude. Would put
Anthropic into direct competition with Lovable/Bolt. **Not public as of
April 2026** per the prior research — but this is the single biggest
unknown in the competitive map. Anthropic has model quality, distribution
(Claude.ai reach), and now reportedly the platform bits.

**Edit model.** Conversational, regenerate-on-request. Artifacts version
history.

**Deploy.** Artifacts: URL-sharable. Full-stack builder: unknown deploy
target (own infra likely).

**Stack.** React + TypeScript + Tailwind primarily.

**Verdict.** If Anthropic ships the leaked builder with payments, it's the
most dangerous competitor because the model quality floor is the highest
in the market. But it's vaporware until shipped.

### ChatGPT (Canvas + Apps SDK)

**Canvas** (March 2024, iterated through 2025): side-by-side code/doc + chat.
Creator can edit code manually or ask Claude/GPT to change it. Not a
deployment platform — it's a coding surface within ChatGPT.

**Apps in ChatGPT** (Oct 2025 GA, App Directory Dec 2025): **MCP-based**.
Creator builds an MCP server hosted anywhere (their infra, Cloudflare,
zeroship, etc.) → registers with ChatGPT → users interact with it in chat.
**OpenAI is a distribution layer, not a hosting platform.** No AI-generated
apps product; creator writes the MCP server themselves.

**Code Interpreter**: Python sandbox — runs data science tasks, not
general apps. Not a builder.

**Verdict.** ChatGPT isn't a competitor to zeroship in the codegen sense —
no AI-generated-app product. It's a **distribution channel** zeroship apps
could plug into via MCP. GPT Store revenue share program is widely viewed
as failed (opaque payouts, most creators earn $0).

### GitHub Spark

**Input.** Text prompt inside github.com.

**Stack.** **TypeScript + React ONLY** — narrow on purpose.

**Deploy.** Spark Hosting (managed). Auto-provisioned **KV storage** + **LLM
API access** + GitHub auth out of the box.

**Edit model.** Agent with tool use; files are git-backed from day one.
Every app is a GitHub repo.

**Models.** **Claude Sonnet, GPT-5, o3** — developer picks per-session.
Unusually open model menu for a first-party tool.

**Pricing.** Bundled into **Copilot Pro+ at $39/mo** — 375 prompts/month,
$0.04-0.16/overage. Dedicated SKU as of Dec 2025.

**Differentiator.** Tighter GitHub integration than anyone — every app is
a versioned repo, Actions/Codespaces work naturally. Positioned for
developers already in the GitHub ecosystem, not non-coders.

**Verdict.** Microsoft's defensive bet. Not a direct threat to zeroship's
non-technical creator positioning, but pulls developer-adjacent prosumers.

### Base44 (inside Wix)

**Pre-acquisition**: Full-stack AI builder, React frontend + custom Node
backend + proprietary "schema builder" DB layer. Solo-founder bootstrapped,
sold for $80M cash to Wix June 2025.

**Inside Wix**: integrated into **Wix Vibe** (Wix's rebranded vibe-coding
push). Uses Wix Studio's hosting + Wix's domain/email/commerce stack.
10,000 companies using (1,300 paid) at acquisition time.

**Verdict.** If Wix connects Base44's AI generation to **Wix Studio's
marketplace + e-commerce infrastructure**, they'd be the closest structural
competitor to zeroship — Wix already does end-user commerce, they just haven't
linked AI-generated apps to it yet. Worth monitoring Wix product announcements.

### Rork

**Input.** Text prompt — mobile-app-framed ("I want an app like...").

**Scope.** **Mobile only**: React Native + Expo; **Swift native** via
Claude Opus 4.6 (added late 2025 — claimed first Swift-on-web codegen that
replaces Xcode).

**Deploy.** **App Store / Google Play submission**. Generates native
binaries (IPA/AAB). This is the unique angle — everyone else ships web or
PWA; Rork ships to the actual app stores.

**Preview.** Real mobile emulator + phone-connect over local network.

**Data/DB.** Firebase / Supabase templates. No proprietary DB.

**Verdict.** The **only competitor targeting consumer mobile creators**.
Positions itself as "for App Store entrepreneurs" — the closest PR
positioning to zeroship's "Shopify for AI apps", but technically and
economically different (it rides Apple's 30%/15% rails, not its own
monetization layer).

### Cursor / Windsurf (for contrast)

**Cursor** (Anysphere): VS Code fork with agent mode, composer multi-file
edits, tab autocomplete via custom model, background agents (Jan 2026).
$2B ARR, $50B val. **Uses any model** (Claude, GPT, Gemini, open-weights)
at user choice. **Deploys nothing** — creator ships their code wherever.

**Windsurf**: similar IDE agent; bought by Cognition (Devin team) for
~$250M after OpenAI's $3B deal collapsed.

**Verdict.** **Not competitors to zeroship** — these are developer IDEs,
not creator platforms. Included for completeness because they're the
highest-revenue tools in the broader AI-codegen market and define what
"agent" means in the category. If a developer uses Cursor, they still need
a platform to deploy to — that platform could be zeroship, Vercel, Cloudflare.

## Emerging Patterns (table stakes by April 2026)

**Auto-provisioned backend is now standard.** Lovable Cloud, Firebase Studio,
GitHub Spark, Emergent, Replit all ship "type a prompt, get a DB + auth + CRUD"
without configuration. Bolt/v0 get close via Supabase/Vercel partnerships.
Not differentiating anymore; **the absence of this is a deal-breaker**.

**Live preview inline.** Every tier-1 tool has it. Bolt's WebContainer variant
is the fastest (truly instant); Lovable/Vercel are near-instant server-rendered.

**Git sync (two-way).** Lovable → GitHub, v0 → GitHub, Bolt → GitHub, Replit
→ Git, Spark = git repos. Expected.

**Visual edit (click-to-change).** Lovable pushed this; v0 has it; others
catching up. Rapidly becoming table stakes.

**Image-to-UI / screenshot-to-app.** v0 led; Lovable added; Bolt has it.
**Figma import** more uneven: Lovable yes, others sporadic.

**Mobile support.** Replit (native via Mobile Apps), Rork (App Store), Bolt
(Expo templates), Firebase Studio (Flutter/iOS). Lovable and v0 are
**web/PWA-only** — a real gap for creators targeting mobile-first audiences.

**Integrated deploy.** One-click to the tool's own platform or a tight
partner: all tier-1 players.

**Chat-first + code-view-optional UX.** Lovable set the idiom; v0 and Bolt
match. Replit is code-first + chat side (more developer-y).

## Feature Gaps Nobody Has Filled

**1. End-user monetization with platform cut** — THE gap.
Every tool monetizes the creator via subscription. None take 15% of what end
users pay creators. This is zeroship's unclaimed territory. (Stripe Billing
integrations in Lovable/Bolt are creator-facing, not marketplace — creator
keeps 100% of the gross, minus Stripe's own ~3%.)

**2. Multi-tenant SaaS generation at scale.**
No tool handles "I want to build a SaaS that serves 1000 paying end users
with per-tenant data isolation" as a first-class concept. AI generates
single-tenant patterns; scaling to multi-tenant requires manual
architecture work.

**3. Schema migrations beyond additive.**
Every tool does `ADD COLUMN IF NOT EXISTS` well. Renaming a column, changing
types, backfilling derived fields — weak everywhere, including zeroship
today. This will bite hard when AI-generated apps try to iterate on production
data.

**4. Typed RPC between client and server.**
Lovable / Bolt / v0 use Supabase SDK or generated fetch calls. Type safety
across the wire is inconsistent. The "use server" / typed RPC story that
Next.js + TanStack Start / Zeroship's vite-plugin transform offers is
**genuinely differentiating** if you lean into it.

**5. Observability for creators.**
Firebase Studio has full Cloud Logging; Replit has logs; Vercel has analytics;
others are weak. Non-technical creators need "my app had an error, here's what
happened" in plain English. Nobody solves this well.

**6. Background jobs / cron.**
Generated apps rarely have background processing. "Email me a daily summary"
requires the creator to configure cron somewhere, which they can't do.

**7. Rate limiting / abuse protection.**
Non-technical creators get DDOS'd and don't know what to do. No tool ships
this as a first-class concept.

**8. File uploads → CDN with transforms.**
Supabase Storage + Vercel Blob + Firebase Storage all work but the AI-generated
upload flow is often fragile (no resumable upload, no image resizing, no
virus scan). Cloudinary / imgproxy-level features don't appear.

**9. Email sending from generated apps.**
Most tools give you "here's a TODO to integrate Resend." No platform bundles
transactional email as a default.

**10. Proper CI / preview environments per pull request.**
Vercel does this for developers, but non-technical creators don't know what a
PR is. "Preview this change before it goes live" as a consumer UX is missing
everywhere.

## UX Innovations 2025-2026

**Bolt's WebContainer** (2022 but productized 2024-25): running Node in the
browser at WASM. No one else has matched the zero-server-cost iteration
architecture.

**Lovable's Visual Edit** (mid-2025): click any element in the live preview
→ chat context narrows to that element's file. Now being copied everywhere.

**Lovable Cloud auto-backend** (Nov 2025): the "no config, just a full
Postgres + auth + storage project per workspace" paradigm.

**v0's streaming generative preview** (throughout 2025): JSX streaming as
the model emits it — watching the UI build itself in real time.

**Replit Agent 3 multi-hour autonomous runs** (Oct 2025): queue a complex
task, close the tab, come back hours later to reviewed code changes.

**Figma → Lovable** (Feb 2025): paste a Figma URL → get a working React
implementation.

**Claude Artifacts window.claude.complete** (Jun 2025): artifacts that call
their parent model's LLM from inside the artifact. Embedded AI in the
generated app without API key management.

**Rork Swift native codegen** (late 2025): Claude Opus 4.6 generating
compilable Swift from prompts — first credible "no Xcode" path for iOS apps.

**Vercel v0 Sandbox** (Feb 2026): ephemeral Node.js runtime for
previewing full-stack changes before deploy.

**GitHub Spark model menu** (2025): first-party tool letting users pick
Claude / GPT-5 / o3 per session — uncommon openness.

## Code Quality Signals

I don't have head-to-head benchmarks to cite cleanly. What I can say
(from public signals and the earlier research):

- **Veracode 2025**: 45% of AI-generated code fails OWASP Top 10. Applies
  to all tools in this space roughly equally.
- **Lovable RLS incident**: 170 / 1,645 Lovable apps had critical database-
  level auth holes. Remediated by Lovable but the data leaked is a category
  warning.
- **METR study (July 2025)**: senior developers using AI tools were **19%
  slower** but felt 20% faster — productivity illusion. Applies to every
  IDE agent.
- **Stack Overflow (Jan 2026)**: declared vibe coding "a new worst coder."
- **"Vibe coding hangover" (Fast Company, Sept 2025)**: organizations
  expecting senior engineers to review and fix vibe-coded features that
  don't work.

**Subjective community ranking for working-code quality** (inferred from
Reddit/Twitter/HN, not authoritative):

1. **Lovable** — polished React UIs that work, weakest at backend complexity
2. **v0** — best UI component quality, weakest at full-stack app
3. **Replit Agent 3** — best at long multi-step tasks, can lose context
4. **Bolt** — best iteration speed, WebContainer limits apply
5. **Firebase Studio** — best for Firebase-native apps; awkward elsewhere
6. **Cursor / Windsurf** — best for *developers* who know what they want
7. **GitHub Spark** — solid but narrow stack
8. **Base44** — unknown post-acquisition quality trajectory

For anything non-trivial (auth, multi-user, real payments), **every tool
requires human code review or it ships with bugs**. This is the strongest
argument against shipping AI-generated apps to end users without a robust
platform between the creator and the real world — which is exactly
zeroship's thesis.

## Strategic Takeaways for zeroship

**Features zeroship already has that map to this landscape**:
- Declarative SDK (`createDb({todos: {text: t.string()}})`) maps to auto-
  provisioned backend pattern — strong
- Typed RPC via `"use server"` transform maps to the typed-wire gap — nobody
  else ships this
- Runtime performance (512K/1.17M req/s) exceeds every competitor's hosted
  runtime, none of them publish benchmarks at this level
- PGlite dev Postgres matches Lovable Cloud's convenience without requiring
  account provisioning

**Features zeroship needs to match table stakes**:
- `@zeroship/storage` (file uploads) — everyone else has it
- `@zeroship/kv` — everyone else has it
- Visual edit / click-to-change — hard to match without a Vite HMR + AI
  context path
- Image-to-UI generation — requires model integration
- Figma import — bundle via third party

**Features zeroship could ship as differentiators**:
- **End-user monetization loop** — the unclaimed #1 gap
- **Multi-tenant SaaS as a first-class primitive** — nobody has it
- **Security posture narrative** — Veracode/RLS incidents give real credibility
  air if you can back it up (sandbox, RLS-aware generation, auto-rate-limit)
- **Observability in plain English** — "your app had 3 errors in the last
  hour, all from user X trying to upload a 50MB file" — nobody does this for
  non-technical creators

**Features that are not worth pursuing**:
- WebContainer-style in-browser runtime (Bolt's moat, takes years to build,
  server-side iteration is fine for zeroship's economics)
- Custom LLM fine-tuning (Vercel's v0 moat is marginal; Lovable uses Claude
  off-the-shelf and is winning)
- Swift native codegen (Rork's niche, narrow TAM for zeroship's thesis)
