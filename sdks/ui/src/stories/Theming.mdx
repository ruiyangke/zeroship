# Theming

`@zeroship/ui` treats theme as a contract, not a palette swap. Every theme
must provide the same semantic `--zs-*` custom properties. Components only
read those properties, so the same Button, Dialog, Table, and form controls
change personality when `data-theme` changes.

Storybook uses `@storybook/addon-themes` with `withThemeByDataAttribute`.
The toolbar writes `studio`, `atelier`, `dusk`, `glass-dark`, or
`glass-light` to `data-theme` on the document element, and every story
re-renders against that contract.

## Contract

Color: `--zs-surface`, `--zs-surface-raised`, `--zs-surface-sunken`,
`--zs-surface-overlay`, `--zs-ink`, `--zs-ink-soft`, `--zs-ink-muted`,
`--zs-accent`, `--zs-accent-hover`, `--zs-accent-ink`,
`--zs-state-success`, `--zs-state-success-bg`, `--zs-state-warn`,
`--zs-state-warn-bg`, `--zs-state-danger`, `--zs-state-danger-bg`,
`--zs-state-info`, `--zs-state-info-bg`, `--zs-rule`,
`--zs-rule-strong`, `--zs-focus`, `--zs-backdrop`, `--zs-code-bg`,
`--zs-code-ink`.

Glass surface effects use `--zs-blur` for panel backdrop filtering and
`--zs-surface-bg` for the root backdrop mesh. Components read both with
fallbacks (`var(--zs-blur, none)` and `var(--zs-surface-bg,
var(--zs-surface))`), so non-glass themes leave them unset and remain flat.

Type, space, radius, shadow, motion, and layer keys are fixed too:
`--zs-font-display`, `--zs-font-body`, `--zs-font-mono`, `--zs-text-*`,
`--zs-space-*`, `--zs-radius-*`, `--zs-shadow-*`, `--zs-motion-*`,
`--zs-z-*`, `--zs-border-*`.

## React Provider

Import the CSS once, then wrap the app:

```tsx
import { ThemeProvider } from "@zeroship/ui";
import "@zeroship/ui/styles.css";

export function Root() {
  return (
    <ThemeProvider defaultTheme="studio">
      <App />
    </ThemeProvider>
  );
}
```

`useTheme()` exposes `{ theme, setTheme, themes }` for a product-level theme
picker. The provider persists to `localStorage` by default and writes
`data-theme` to the document element.

## Adding A Theme

Add a new `[data-theme="name"]` block in `styles.css`, provide every required
contract key, add the name to `themes` and `themeLabels`, then add it to the
Storybook toolbar. Components do not change unless the new theme needs a new
semantic token.

The same markup below restyles as you flip the toolbar theme:

<div className="zs-story-row" style={{ display: "flex", gap: "var(--zs-space-3)", flexWrap: "wrap", padding: "var(--zs-space-6)", background: "var(--zs-surface-bg, var(--zs-surface))", borderRadius: "var(--zs-radius-md)", border: "var(--zs-border-sm) solid var(--zs-rule)" }}>
  <Button>Primary action</Button>
  <Button variant="secondary">Secondary</Button>
  <Button variant="ghost">Ghost</Button>
</div>
